# AnimationLab Portable compatibility

## What transferred

| Workflow | Portable support | Boundary |
| --- | --- | --- |
| Layered 2D and motion graphics | Pillow CPU, browser Canvas, and PixiJS 8. Programmatic articulated cutouts, frame-based poses, masks, vector drawing, sprite sheets, seeded movement and parallax. | The Pillow lane uses its own authored scene code and Pillow drawing, treatment and compositing primitives. Pixi and Canvas scene modules require Chromium. |
| 2D skeletal animation | Rigby2D 0.6.0 Pixi runtime for compatible JSON or binary skeleton and atlas assets. The Scout example renders an original articulated atlas and a frame-stepped effect. | Desktop Rigby editor, proprietary mascot assets, other engine runtime ports and editor-only tools are separate. Export or supply the rig and its textures. |
| Multiplane 2.5D | Pillow/Canvas layers with camera-relative motion and Three.js world cameras, lights, fog and composited HUD. | Alternate implementations are authored per shot. Art and composition need matching across mixed engines. |
| Stylized 3D | Three.js r170 with local GLTFLoader, toon materials, shadows, seeded procedural scenery and camera helpers. Signal Break retains a skinned VRM 0.x actor, hand and foot IK, facial morphs, finger poses and authored secondary motion. | Three and Pixi require a working WebGL2 context. SwiftShader is the default. VRM 1.0, automatic weight painting and physically solved secondary motion are outside the supplied rig. |
| Cinematic VFX | The original camera, environmental shaders, 2D rig, HUD and composer are included. Use authored impact poses, smears, speed lines, trails, particles, shockwaves, emissive effects, camera shake and fog. The browser composer scales lighting and post effects by profile. | Effects require authoring per scene. Custom shaders, high-resolution blur, heavy geometry and large particle counts can exceed the available CPU time. |
| Blender | Optional 3.4+ shot adapter with an offline Cycles CPU template, samples and threads. It accepts an optional blend project with a compatible frame-output script. The sample leaves Cycles denoising opt-in because the Debian build lacks OpenImageDenoise. | File/API compatibility depends on the script and installed Blender. The 3.4 baseline does not promise compatibility with 5.x project files, new Grease Pencil APIs or GPU-only feature paths. |
| Godot | Optional Godot 4 adapter, software GL Compatibility mode, isolated imports and Movie Maker capture. The installer can fetch a pinned official x86-64 binary. | Needs a real or virtual display and Mesa GL on Linux. Projects written for Forward+ shaders, compute, or specific Godot 4 minor versions may require changes. Missing Godot leaves the other lanes usable. |
| Audio and narration | Recorded or externally sourced audio via FFmpeg, eSpeak NG CLI or CPU wheel, optional Kokoro INT8 ONNX, seeded music and SFX, stereo pan and ducking, R128 gain and AAC. | Model and voices are opt-in. Credentials and hosted TTS integrations are outside the source package. A compatible Rhubarb executable can be supplied separately for lip cues. |
| Subtitle timing | Author-supplied word cues or proportional word estimates from actual take duration, monotonic ASS captions and burn-in. | Proportional timings estimate coverage and require review where word-accurate synchronization matters. CUDA WhisperX, PyTorch and downloaded alignment weights are excluded. |
| Delivery/QC | Frame-quantized cut/xfade, normalized square-pixel BT.709, H.264/AAC, exact frame/dimension/cadence checks, full decode, A/V length check, AAC loudness/true peak, contact sheet and FFmpeg motion flags. | The original OpenCV/PySceneDetect gate is replaced by cheap blank/freeze signals and a targeted visual pass. SDR tags and common transport do not match the artistic grade between engines. |

## Source audit and disposition

The inventory covered all 23 top-level entries and counted logical file sizes without following junctions. I used the root and pipeline READMEs, architecture review, Windows benchmarks, production upgrade, dependency manifests, the compatibility and optimization reports, the Pixi emitter investigation, the project-local skill and the actual active source to select the transfer.

| Original area | Classification and disposition |
| --- | --- |
| pipeline/core, audio, renderers, vendor and templates | Essential. Retained frame clock, cache, scene contracts, Three vendor and loaders, Canvas rig and effects, HDR composer and camera, FFmpeg assembly, audio synthesis and captions. Adapted paths, permissions, encoding, behavior on missing engines and CPU budgets in the staging copy. |
| pipeline/demos, test-outputs and StyleBenchmark | Existing demonstrations and performance evidence. The four active demos informed tests. Bundled the editable Signal Break reference with its credited VRM and added much smaller engine proofs. Historical videos, frame caches and style gallery were omitted. |
| sandboxes/pixi-suite and rigby2d-demo, character-tools/rigby2d | Valuable runtime. Use PixiJS 8.23.0 and its compatible barvynkoa emitter, plus the pinned published Rigby Pixi runtime. Install via the lockfile. The official older emitter, duplicate source trees, browser payloads, editor builds and mascot art were excluded. |
| Godot, Blender, portable/rhubarb, character-tools/pixelorama | Optional. Runtime can use external Godot, Blender and Rhubarb where available. Windows launchers/executables were excluded. Pixelorama remains an external art tool and its exported sprite sheets can be used here. |
| launchers and .cache | Windows-specific orchestration and regenerable data. Bootstrap and the shell wrapper replace the relevant PowerShell behavior. Caches, copied installers and render products are excluded. |
| models, envs and ai-and-depth | GPU-heavy and downloaded dependencies. Kokoro INT8 CPU downloads only on request. eSpeak, authored timestamps and FFmpeg motion checks cover lightweight production. CUDA, Depth Anything model weights, cu128 wheels, Torch, WhisperX, and the large local virtual environments are outside the distribution. |
| engines, experimental, other sandboxes and _archive | Useful research and niche exporters, or redundant clones for this release. Manim, Motion Canvas, Remotion and the Lemo-Opuscar/Huashu/Anidoodle libraries remain in the original lab. They can supply compatible image sequences or audio sources when appropriate. |
| User projects and large previous films | Original Gravity, Chakra, Senku projects and Low Tide remain in place. The portable folder carries reusable pipeline features and licensed example inputs. |
| .agents and reports | The director was adapted with its attribution and selected references. Historical Windows reports informed the audit. This release ships its own transfer and compatibility notes. |

## Gemini baseline and checks

The target supplied by the owner is Debian 12 x86-64 with two vCPUs, about 6.8 GiB available RAM, 42 GB free and no GPU. The installer probes locally rather than trusting those values. It checks the FFmpeg 5.1+ feature set, Python 3.11+, Node 18+, Chromium Canvas/WebGL2 and Pixi, Blender 3.4+ and Godot 4 with a display path. On the target, use one short representative timed render per proposed profile before committing to a 50–60 second film.

Current Chromium is reused after a Playwright probe. The pinned Playwright version supports Node 18. Using it with a different system Chromium still depends on the installed build. The headline Windows GPU benchmarks of the original are historical, and CPU results can vary substantially with the scene and machine.
